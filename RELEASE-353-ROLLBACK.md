# Ручной план отката KVAS 353

Процедура предназначена для будущей ручной установки и не выполняется
скриптами сборки.

## До установки

1. Оставить рабочий OpenVPN выбранным резервным подключением.
2. Сохранить текущие файлы KVAS, Xray, DNS-посредника, обработчиков и rescue.
3. Подготовить полный совместимый IPK 353, собранный через
   `tools/build-ipk.sh --compat-352`, и проверить checksum. Не использовать
   `--surgical` для обновления установленного пакета через `opkg`.
4. Учесть, что релиз содержит защиту от повторного RCI-up Proxy21 и от
   повторного `link_reboot` VLESS при отказе интерфейса.
4. Обеспечить независимый доступ через консоль или LAN.
5. Зафиксировать WAN-интерфейс, шлюз, default route и прямой доступ в интернет.

## Откат

При неудачном переключении VLESS новый fail-closed механизм не переключает
VPN автоматически. Он сохраняет предыдущий интерфейс и создаёт:

    /opt/rescue/kvas-vless-rollback.md
    /opt/rescue/kvas-vless-rollback.sh

Из независимой консоли или оставшегося SSH-сеанса выполнить:

    /opt/rescue/kvas-vless-rollback.sh

Скрипт восстанавливает сохранённый интерфейс OpenVPN/KVAS и пересоздаёт его
правила. Он не изменяет main default route напрямую.

Для отката версии самого пакета (отдельный сценарий, не первый шаг после
ошибки VLESS) не переключать VPN повторно. Из независимой консоли или SSH
выполнить:

    opkg install /opt/tmp/kvas_1.1.9_beta-10-352_all.ipk

Затем восстановить локальные ссылки S97xray и файлы из резервной копии,
перезапустить только затронутые службы и проверить WAN, DNS и OpenVPN.

При изменении default route, недоступности шлюза, отказе LAN DNS или потере SSH
немедленно прекратить эксперименты и использовать независимый путь восстановления.
Не выполнять очистку всех маршрутов/iptables и не удалять Proxy21 первым действием.
