# Диагностический сценарий: Xray уже работает, затем активируется Proxy21

Сценарий подготовлен, но не запускался. Он предназначен для локализации
проблемы между рабочим SOCKS5/Xray и активацией интерфейса Proxy21.

## Что проверяется

1. До теста подтверждаются WAN-маршрут и подключённый OpenVPN2.
2. Через SOCKS5 выполняется базовая проверка Xray.
3. Сохраняется штатное состояние для отката.
4. Xray и SOCKS5 должны быть запущены заранее; сценарий их не перезапускает.
5. Вызывается только `vpn_on t2s21` — без `kvas vpn set vless` и без запуска
   `S97xray`.
6. Снимаются `ip rule`, table 1001, Proxy21, mangle-правила, сокеты, DNS/IP
   домена и счётчики `KVAS_MARK`.
7. В конце штатный rollback возвращает предыдущий интерфейс, обычно OpenVPN2.

Сценарий не меняет main table, не выполняет `iptables -F` и не делает
`ip route flush table all`. DNS-конфигурация не изменяется.

## Подготовка на роутере

```sh
chmod 700 /opt/tmp/diagnose-vless-preserve-xray.sh
sha256sum /opt/tmp/diagnose-vless-preserve-xray.sh
/opt/tmp/diagnose-vless-preserve-xray.sh --help
```

Для будущего запуска потребуется выбрать домен, который действительно входит в
`KVAS_LIST`:

```sh
/opt/tmp/diagnose-vless-preserve-xray.sh --execute --domain <домен> --url https://<домен>/
```

## Откат и результаты

Результаты сохраняются в `/opt/rescue/kvas-vless-preserve-xray/YYYYMMDD-HHMMSS/`.
Независимое окно SSH должно оставаться открытым. При проблеме вручную выполнить:

```sh
/opt/rescue/kvas-vless-rollback.sh
ip route get 1.1.1.1
ip route show table 1001
/opt/bin/kvas vpn
```

Автоматический rollback через `trap` предусмотрен при штатном завершении,
ошибке и сигнале. Если SSH-сессия оборвётся до выполнения `trap`, используется
независимое окно SSH и приведённая команда rollback.
